# WebGL 移动端横屏画布设计

## 目标

让 Unity WebGL 游戏在 iOS 与 Android 浏览器中始终以横屏画面呈现。用户将设备从横向转为竖向时，游戏内容仍保持横向，且不出现阻断游戏的旋转提示。

## 平台策略

### Android

在用户首次触摸或点击后，尝试调用 `screen.orientation.lock('landscape')` 锁定系统显示方向。该调用依赖浏览器的权限、上下文与版本；失败时不报错，回退至画布横屏布局。

### iOS Safari

iOS 浏览器网页无法可靠锁定系统方向，因此不依赖方向锁定。页面根据当前视口方向调整 Unity 容器：横屏时正常填满视口；竖屏时旋转并重新定位容器，使 Unity 继续按横屏坐标系渲染。

## 页面行为

1. 删除竖屏时显示“请横屏使用”的遮罩及其 JavaScript 双保险逻辑。
2. 保留单一的 CSS 横竖屏布局规则；竖屏状态下不隐藏 `#unity-container`。
3. Unity canvas 始终占满容器；安全区、加载条与构建时间随容器一起旋转。
4. 方向变化或窗口尺寸变化后，浏览器重新计算 CSS 媒体查询，无需重建 Unity 实例。

## 错误处理与兼容性

- `screen.orientation.lock` 不可用或被拒绝时静默降级，游戏仍可游玩。
- 不请求 Fullscreen API，也不把隐藏浏览器地址栏作为本变更的成功条件。
- PWA 独立模式与普通浏览器模式均使用同一画布布局。

## 验收标准

- Android Chrome：横屏进入游戏后尝试锁定横屏；转动设备时，若锁定失败，游戏画面仍为横向。
- iOS Safari：横、竖持机均不显示旋转提示；竖持时游戏画面为横向，Unity 内容不被隐藏或重载。
- 桌面浏览器：保持全视口横屏画布与现有加载流程。
- 现有全屏按钮和 Unity 构建资源加载不受影响。
