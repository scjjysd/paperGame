# 保留手绘形状的矩形碰撞设计

## 目标与范围

修正细长空心矩形被识别为上下两条平台，以及 L 形被整体外接矩形填满的问题。用户已确认采用「保留形状、拆分成多个矩形」方案，仍直接修改原工程，保留其他未提交改动。

本次主要修改服务端；Unity 已支持 `blocks[].region` 的实际宽高矩形碰撞，不增加协议字段。同步允许只有 `blocks` 而没有线平台的关卡，并停止旧调试面板的运行时可达性分析。平台、墙是用途分类，底层继续统一使用矩形碰撞体。

## 几何规则

1. 起点圆圈与终点旗帜优先识别，标记自身不生成碰撞几何。相连的平台不得因为与旗帜接触而整条丢失。
2. 独立水平、竖直单线保留现有 `platforms`、`walls` 输出和固定 `GroundThickness`，不强行按墨迹笔宽生成障碍。
3. 真实闭合长方形（包括细长、略倾斜、曝光不均的手绘轮廓）填充其内部，再输出有实际宽高的矩形，不输出重复边线。
4. 空心闭合多边形填充内部；实心多边形直接使用其形状。凹形不得用整个外接矩形替代。
5. L 形拆分为横向、竖向两个主要矩形，允许接合处相接或少量重叠，但不得产生填满凹角的大矩形。
6. 其他复杂多边形分解为多个轴对齐矩形。以原图像素形状为依据，仅允许少量边界近似误差；斜边可形成阶梯矩形，不承诺任意斜边只用一个矩形。
7. 开放的相邻平行线不能仅因形态学桥接而成为实体；只对有可信闭合证据的小缺口进行修补，禁止跨较大空白补成封闭图形。

## 实现边界

新增专注的几何拆分模块，输入经过标记排除及闭合/实心证据校验的单个形状掩码，输出矩形区域列表。采用水平区间扫描与相邻行区间合并；对手绘边缘进行受限简化，优先合并能由一个矩形近似的长方形，凹形按区间变化拆分。矩形数量设置上限，超过上限应降低边界精度后重新拆分或舍弃不可靠候选，不能回退为填满凹角的外接矩形。

实现采用单个主体最多 32 个矩形；轮廓简化基础容差为 3px，近水平/竖直边归一修正最多 12px（900×560 画布）。发布时保留主体来源和矩形成员身份，并检查边界误差，不用内部矩形是否有笔迹来判断是否可信。原图有拍摄倾斜和手绘弯曲，轴对齐矩形是受限近似，并非逐像素复刻。

检测层维护两份几何：用于矩形输出的形状，以及用于排除重复边线的原轮廓掩码。不能只用一个大外接区域排除线段，否则会删除凹角空白中的独立平台。

所有矩形仍发布到 `blocks`，区域有稳定排序、唯一 ID、画布边界和置信度校验。单线继续使用已有两种数组。可达性仍为 `not_checked`；正常生成仍要求唯一明确起点和终点。

缓存盐升级为 `explicit-markers-v4`，使同图重新上传不会命中 v3 结果。旧保存 JSON 不会自动更新，需重新生成。

## 验收与测试

- 合成长矩形及曝光偏灰、轻微倾斜长矩形：只有矩形障碍，无上下边重复平台，实际厚度接近手绘厚度。
- 空心、实心 L 形及镜像方向：两个主要矩形；凹角指定空白点不被任何矩形覆盖，横向和竖向主体均有碰撞覆盖。
- 十字、阶梯等复杂凹形：主体覆盖、凹空白保持，输出数受限、顺序稳定。
- 开放平行线、小文字、纸边阴影：不误判为闭合实体。
- 圆圈、旗帜及相连平台：标记无重复几何，平台主体保留。
- 用户这次完整截图与局部 L 形截图作为真实回归输入，验证对应轮廓；截图中的绿框和编辑器图标不当作原始墨迹。若能取得该任务原始 input/rectified 图，优先使用原图进行端到端验收，不能仅凭合成图宣称实拍已修复。
- 复跑检测、标记、发布、协议及缓存测试；已有无关 WebGL 回归失败单独记录，不修改无关页面。
- Unity 已有矩形尺寸测试复跑；若数据格式不变，不改客户端生产代码。

## 非目标

不增加致死墙、可玩性判断、强制生成勾选框，不修改首页 UI 或发布配置。上线需部署服务端并重启 API/Worker，重新构建客户端以包含全矩形关卡兼容和停止运行时可达性分析的修正。
